# Color

`color()` paints faces or whole solids. Colours are part of the model: they survive later features, follow the geometry through fillets and booleans, and are written into STEP exports.

Paint from the **Color** tool on the toolbar, or write the statement in the editor: select the faces (a `select()` with a [filter](/docs/3d-operations/selection-and-filters), or a feature accessor such as `e.endFaces()`), then call `color()` with a CSS colour: a name (`"red"`, `"steelblue"`), a hex value (`"#e74c3c"`) or an `rgb(...)` string.

## In the viewport

1. Click **Color** on the toolbar. The dialog opens on the **Solid** tab; faces already selected open it on the **Face** tab with those faces picked.
2. Choose the colour: pick one from the colour well, type a value in the field — a hex value (`#3498db`), a CSS colour name (`steelblue`) or an `rgb(…)` string — or click a swatch.
3. On the **Solid** tab, click a face or edge of each solid to paint whole, or its feature row in the timeline. Every face of the solid takes the colour. On the **Face** tab, click the faces to paint; double-click a face to take its whole group (every end face of an extrude, say), or right-click one for the same multi-select menu the Fillet tool offers.
4. The picks show in the chosen colour as you go, and the preview under the dialog reads the statement the tool will write. On the Face tab the expression row shows the selector the picks resolve to; edit it, or pick an alternative from its dropdown, to write that instead.
5. Click **Apply**. FluidCAD adds a Color feature to the timeline and writes `color('steelblue', e)` for whole solids or `color('steelblue', e.endFaces())` for faces.

To change an existing colour, double-click its timeline row. The dialog reopens on the tab the statement uses — whole objects as chips to keep, remove or add to, painted faces as picks to re-pick — with the colour in the field.

## Colouring a selection

`color()` with one argument paints the last selection. With no selection at all it paints every face in the current context:

```js
select(face().parallelTo("xy"))
color("#3498db")               // every horizontal face

select(face().cylinder())
color("silver")                // every cylindrical face
```

## Colouring a whole object

Pass a scene object instead of faces and every face of its solids is painted — the quickest way to give a part a base colour, which single faces can then override:

```js
const body = extrude(30)
color("steelblue", body)       // base colour for every face

select(face().onPlane("xy", 30))
color("tomato")                // repaint just the top face
```

One statement takes any number of targets — several objects, several selections, or a mix:

```js
color("silver", body, lid)              // both solids
color("gold", body.endFaces(), lid.endFaces())
```

## Colour never consumes a selection

A colour changes no geometry, so it takes nothing away from the model. The solid stays with the feature that built it, and a selection you pass to `color()` is still there for the next feature:

```js
const top = select(face().top())
color("orange", top)           // paints the top face
fillet(2, top)                 // the same selection, still usable
```

A bare `color()` claims the last selection like any other feature, so a bare `fillet(2)` written after it starts from no selection rather than inheriting the painted faces.

`color(value, object)` paints the object's bodies as they stand at that statement. If a fillet or a boolean has already taken the object's solid, the paint lands on the body those features made of it — `color("steelblue", body)` after `fillet(2, body.endEdges())` paints the filleted body, arc faces included.

When two statements paint the same face, the **last `color()` wins**. Scrubbing the timeline follows the same rule: stop on the row before a paint and the body is shown unpainted; stop between two paints on one face and the earlier colour is shown.

## Colours survive later features

Paint a face, then keep modelling: fillet, chamfer, fuse, cut and the rest carry colours forward onto the faces they produce.

![Color preserved through fillet](/img/docs/appearance/color-survives-fillet.png)

<ExplainedCode code={colorSurvivesFillet} fileName="fillet-color.part.js">
The top face is painted before the fillet. After it, the trimmed top face is still orange, and so is the fillet's arc face — colours transfer onto modified faces and bleed onto the new geometry next to them.
</ExplainedCode>

When a coloured face is split — by a cut across it, say — every surviving piece keeps the colour. When a coloured face is removed entirely, its colour goes with it.

## Colour bleeding

New geometry fused into a coloured shape inherits the colour of the faces around it:

![Color bleeding onto fused geometry](/img/docs/appearance/color-bleeding.png)

<ExplainedCode code={colorBleeding} fileName="bleed.part.js" />

Bleeding only reaches faces that came from **new** geometry. Faces that already existed and were left uncoloured stay uncoloured. The same rule covers fillet arcs, chamfer surfaces and the section faces of a cut.

## Explicit `fuse()` color rule

In a [fuse](/docs/booleans/fuse) the **first input is dominant**:

- if the first input carries colours, they propagate to the result and bleed onto the other inputs;
- if the first input has no colours, the result is uncoloured even when other inputs were painted.

![fuse() first input dominates](/img/docs/appearance/color-fuse-first-input.png)

<ExplainedCode code={colorFuseFirstInput} fileName="fuse-first.part.js" />

With an uncoloured first input nothing propagates — painting later inputs has no effect on the result:

![fuse() first input uncolored — result stays uncolored](/img/docs/appearance/color-fuse-first-uncolored.png)

<ExplainedCode code={colorFuseFirstUncolored} fileName="fuse-uncolored.part.js" />

So the order of the Boolean dialog's **Solids** chips — the argument order — chooses whose colouring wins: put the solid whose colours you want to keep first.

## Export

Colours go into STEP files (the export dialog's colour toggle and the CLI's `--no-colors` flag turn that off) and are shown for imported STEP files that carry them. See [Export](/docs/import-export/export).
