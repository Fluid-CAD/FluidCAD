# Planes

A plane is a flat reference: the surface a sketch is drawn on, the mirror of a mirror feature, the halfway mark between two faces. Every model starts with the three origin planes, and the **Plane** tool derives new ones from them or from existing geometry.

## The origin planes

Three planes exist in every file without any statement. They are named by the world axes they contain and have an alias each, plus a flipped version whose normal points the other way:

| Name | Alias | Normal | Flipped | Flipped alias |
|------|-------|--------|---------|---------------|
| `"xy"` | `"top"` | +Z | `"-xy"` | `"bottom"` |
| `"xz"` | `"front"` | −Y | `"-xz"` | `"back"` |
| `"yz"` | `"right"` | +X | `"-yz"` | `"left"` |

In the viewport they show as three small quads at the origin. Clicking a quad while a dialog's plane slot is armed picks that plane; the **Sketch** tool's **Face / Plane** slot accepts them the same way.

```js
sketch("xy", () => { ... })      // draw on the ground plane
sketch("front", () => { ... })   // same as "xz"
mirror("yz")                     // mirror the model across the YZ plane
```

## In the viewport

1. Click **Plane** on the toolbar. The Plane dialog docks on the right.
2. Pick the **type** at the top: **Offset**, **Mid plane** or **From edge**.
3. Fill the **Base** slot from the scene: click a face in the viewport, an origin-plane quad, or a plane row in the timeline. **Mid plane** takes two bases; **From edge** takes an edge. Once the slot is full, only the origin planes you chose stay in the viewport, so the ghost reads clearly against them; clicking a chosen quad again, or the chip's ✕, frees the slot and brings the others back.
4. Enter the **Distance** (Offset type) or the **position** along the edge from 0 to 1 (From edge type). Offset and Mid planes also take a rotation per axis, in degrees, and a choice of which axes the turns are around: **Local** (the plane's own X, Y and normal, so it tilts in place) or **World** (the world X, Y and Z axes through the origin, so an offset plane swings around them).
5. Click **Apply**. The plane appears as a translucent quad in the viewport and as a row in the timeline, and a `plane()` statement is written to the file. Clicking that quad later picks the plane for a sketch or a mirror.

A plane is not used up by the feature that takes it. A sketch drawn on it or a mirror across it takes the quad off the screen from that feature on, but the plane stays available: every plane slot lists it, named after the feature that used it (`top · used by Sketch`), click its row in the timeline to pick it, and the dialog draws the quad again for as long as it holds it. To see a used plane outside a dialog, click the eye on its timeline row.


A translucent ghost of the plane follows the fields while the dialog is open. Double-click the plane's timeline row to reopen the dialog and edit it.

## Offset planes

The most common plane: an origin plane or a face, shifted along its normal. In the viewport a plane is a translucent square with an arrow at its centre pointing along the normal — the side a sketch on it faces, and the direction a positive offset moves it.

![The XY origin plane offset 40: a plane quad floating 40 above the grid](/img/docs/datums/datums-plane-offset.png)

<ExplainedCode code={planeOffset} fileName="offset.part.js" />

The offset is one of the transform options. The others rotate the plane, and they compose — the offset is applied first, then the rotations. By default the rotations are around the plane's own axes: X first, then Y and the normal as the earlier turns left them. Those axes pass through the plane's origin, so the plane tilts in place. With `rotationAxes: "world"` the rotations are around the world X, Y and Z instead, in that order — the axis lines through the world origin, so an offset plane swings around them rather than tilting where it is:

```js
plane("xy", 50)                                  // shorthand: offset only
plane("xy", { offset: 50 })                      // same
plane("xz", { rotateX: 45 })                     // tilted 45° around the plane's X
plane("xy", { offset: 30, rotateZ: 90 })         // shifted, then spun around its normal
plane("xz", { rotateY: 30, rotationAxes: "world" })      // turned 30° around the world Y axis
plane("yz", { offset: 20, rotateZ: 30, rotationAxes: "world" }) // a radial plane: pushed out 20, swung 30° around Z
```

The two readings differ in the axes and in the pivot. The XZ plane's own Y is the world Z, so `rotateY: 90` swings it to stand in YZ, while the same turn around the world Y leaves it in XZ and spins it in place. And an XY plane offset 30 with `rotateX: 90` stays 30 up and tilts on the spot, while with `rotationAxes: "world"` it swings down around the X axis to stand 30 along −Y.

### From a face

A face is a plane too. Pick the face as the **Base** and the plane takes its position and orientation, centred on the face; the **Distance** offsets it from there:

![A block with a plane 20 above its top face](/img/docs/datums/datums-plane-offset-face.png)

<ExplainedCode code={planeOffsetFace} fileName="block.part.js" />

In code, a number or an options object offsets and rotates the face's plane:

```js
plane(block.endFaces())                  // the top face's plane
plane(block.endFaces(), 20)              // 20 above the top face
plane(block.endFaces(), { rotateY: 15 }) // tilted around the face's Y
```

Sketching directly on a face (`sketch(e.endFaces(), …)`) is the same thing without the separate statement; a `plane()` feature is worth it when several features share the plane, or when it needs an offset or a tilt.

## Mid planes

A plane halfway between two others, oriented like them. Pick two plane rows in the timeline (or two origin-plane quads) as the **Bases**:

![The mid plane between the YZ origin plane and the same plane shifted 60 along X](/img/docs/datums/datums-plane-mid.png)

<ExplainedCode code={planeMid} fileName="mid.part.js" />

The two source planes are folded into the result: after **Apply** only the mid plane shows in the viewport, and the bases stay available to later features like any used plane. It keeps tracking its bases — move either one and the mid plane re-centres.


### Between two faces

The bases can be faces: click the block's bottom face and its top face and the plane lands at mid-height.

![A block with the mid plane between its bottom and top faces](/img/docs/datums/datums-plane-mid-faces.png)

<ExplainedCode code={planeMidFaces} fileName="block.part.js" />

Both arguments must be planes, so a face selection is wrapped in `plane(…)` as above. Options apply to the result:

```js
plane("yz", plane("yz", 60))       // same as the first example, inline
plane(p1, p2, { rotateX: 10 })     // the mid plane, then tilted 10°
```

## Planes from an edge

A plane can also stand **normal to an edge** at a point along it: the edge's tangent becomes the plane normal, so on a curved edge the plane turns with the curve. This is how a profile is positioned for a sweep along a path. The edge can be a solid's edge or an open sketch curve. Pick it as the **Base** and set the **position** along it:

![An arc drawn on the front plane with a plane standing across its midpoint](/img/docs/datums/datums-plane-from-edge.png)

<ExplainedCode code={planeFromEdge} fileName="path.part.js" />

The position is a name or a normalised value:

```js
plane(path, 'start')             // at the edge start — normal faces outward, like a cap
plane(path, 'middle')            // halfway; same as 0.5
plane(path, 'end')               // at the end
plane(path, 0.25)                // a quarter of the way along
plane(solid.endEdges(0), 'end')  // a solid's edge works the same way
```

A sketch that draws a single curve reads as that curve, which is what the dialog writes when a bare sketch curve is picked. A sketch with several curves is picked by edge instead.

At `'start'` (0) the normal faces away from the edge body so both ends read like end caps; `'middle'` and `'end'` follow the edge's forward direction. On a curved edge the plane turns with the tangent.

## Using a plane

| Use | Statement |
|-----|-----------|
| Sketch on it | `sketch(p, () => { ... })` |
| Mirror across it | `mirror(p)` or `repeat("mirror", p, feature)` |
| Wrap onto a face | the sketch plane's origin and orientation place the decal — see [Wrap](/docs/3d-operations/wrap) |
| Loft or sweep profiles | each profile is a sketch on its own plane — see [Loft](/docs/3d-operations/loft) |
| Filter by it | `face().onPlane("xy", 30)`, `edge().parallelTo("xz")` — see [Selection & Filters](/docs/3d-operations/selection-and-filters) |

The same plane can serve several of these in a row — two sketches on one offset plane, then a mirror across it — by variable, with no marker: its first user only hides the quad. See [Reusable Objects](/docs/extra/reusable-objects).

A sketch plane's coordinates are the plane's own 2D frame: `[0, 0]` is the plane origin, X and Y its in-plane axes. Inside the sketch, `xAxis()` / `yAxis()` name those axes — as constraint targets and as directions for the 2D transforms — see [Axes](/docs/datums/axes).
