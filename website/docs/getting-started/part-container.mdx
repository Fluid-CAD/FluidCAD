# Creating a part container

Over the next eight pages you build a butt hinge: two leaves with interleaving knuckles, a pin through them, and a joint that swings the hinge open and shut.

<ViewerEmbed packageId={viewerPackages["assembly"].id} poster="/img/docs/getting-started/hinge-assembly.png" alt="The finished hinge" />

Every page ends with a picture like this one; press play on it to load that step into the browser viewer, spin it around, and open its files.

This page creates the file for the first leaf and puts a **part container** in it.

## Do you need a part container?

A `.part.js` file can hold bare modelling statements. Sketch, extrude, fillet at the top level and the file renders. The `part()` container is not required, but it is recommended even for a part you only ever look at on its own: it is what gives the part parameters, properties and a material.

It is required as soon as the part is going to be **inserted into an assembly**. An assembly imports the file and inserts an *exported part definition*, so the leaf needs `export const fixedLeaf = part('Fixed leaf', () => { … })` around its features. The container is also what connectors and exposed geometry attach to. Since this leaf ends up in a hinge, start with the container.

## In the viewport

1. Click **+** at the end of the tab strip. A box opens with every file in the workspace; type a name that does not exist yet, `hinge-leaf-fixed.part.js`, and press <kbd>Enter</kbd>. The file is created and opens as a tab. (Any editor works too: the server watches the folder.)
2. Click **Part** on the toolbar. It appends an empty part to the file and the History panel shows a **Part 1** row.
3. Right-click the row and choose **Rename**. Type `Fixed leaf`. The name is written into the `part('…')` statement and becomes the part's display name everywhere: the History panel, the assembly's Parts list, the STEP export. The variable the part is exported by is renamed after it, to `fixedLeaf`.
4. Open the code editor (the `</>` button on the left rail, or <kbd>Ctrl</kbd>+<kbd>B</kbd>) to see the statement: `export const fixedLeaf = part('Fixed leaf', () => {})`. The export is what the assembly will import later.

Nothing renders yet: the part is empty. The History panel shows the part row, and every feature you add from now on lands inside it.

:::note
Statements you add while a part row is active go inside that part. The active part is the highlighted row with a dot after its name in the History panel; click a part row to make it active. Click the active part again to step out of it: the dot goes, the row loses its highlight and reads like any other part row, and new statements go at the top level of the file, after the part. Click the row once more to step back in.
:::
