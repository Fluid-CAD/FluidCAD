# Import

FluidCAD imports STEP files. An import becomes a cached `.brep` in the project's `imports/` folder and a `load()` statement in your file, which places the geometry in the scene like any other feature.

A 2D drawing is imported into a sketch instead: the sketch toolbar's **DXF** and **SVG** tools write a file's curves as sketch geometry. See [Import DXF](/docs/sketching/tools/import-dxf) and [Import SVG](/docs/sketching/tools/import-svg).

## In the viewport

1. Click **Import** (the file icon at the right end of the top bar, next to Export). On a narrow window it sits in the **Actions** menu.
2. Pick a `.step` or `.stp` file. FluidCAD converts it and saves it as `imports/<filename>.brep` in your project folder.
3. A `load()` statement is appended to the current file and the imported geometry appears in the viewport with a **Load** row in the History panel. Colors stored in the STEP file are kept.

The project structure looks like this after importing:

```
my-hinge/
├── imports/
│   └── bracket.brep           ← created by the import button
├── box.part.js
└── package.json
```

## What is imported

| In the STEP file | In FluidCAD |
|------------------|-------------|
| Solids | One solid each. |
| Surfaces: connected faces that enclose no volume | One surface each, shaded, with its open rim drawn in the accent color. You can hover and pick its faces and edges from either side. |
| A face on its own | A surface of one face. |
| Curves: edges that bound no face | One curve each. |
| Face colors | Kept on solids and surfaces. |
| Loose points and annotations | Not imported. |

A STEP file stores a curve of several edges as separate edges, so a curve that was one chain in the program that wrote it arrives as one curve per edge.

The cached `.brep` is what the file held when you imported it. A cache that holds only solids gains the file's surfaces and curves when you import the file again: click **Import** and pick the same file. The `load()` statement stays as it is.

## The code behind it

```js
import { load } from 'fluidcad/core';

const bracket = load("bracket");   // loads imports/bracket.brep
```

`load()` takes the file name without its extension and returns a scene object you can transform, select from, and mate against like a modelled solid.

## Loading part of a file

`.include()` keeps only the shapes at the indices you list, and `.exclude()` drops them. The indices count every solid of the file first, then every surface, then every curve, so a solid keeps its index whatever else the file holds:

```js
import { load } from 'fluidcad/core';

load("pump").include(0);      // the first solid only
load("pump").exclude(2, 3);   // everything but the shapes at 2 and 3
load("pump").noColors();      // the geometry without the file's colors
```

## Placing the imported geometry

After loading, move and rotate the geometry with the transform statements:

```js
import { load, rotate, translate } from 'fluidcad/core';

const rail = load("EGH20CA1R350Z0H_FILE_1")
rotate("x", 90)
translate(0, -50, 25)
```

See [Transforms](/docs/transforms/introduction).

## Sharing

A share link carries the geometry the model loads: each `imports/<name>.brep` a `load()` reads, with its colour and unit files, travels in the link beside the source, and the viewer opens the model as the desktop renders it. Imports the model does not load stay out. Because the geometry is in the link itself, a large import can push the link past its size limit; the Share dialog then names the imported file as what makes it too large.

## In a package

A part of a [package](/docs/packages) loads the package's own imports: `load("motor")` written in the package's files reads `imports/motor.brep` from the package, which carries it, never from the project that uses the package. One the package lacks is an error naming the package:

```
Imported asset not found: imports/motor.brep in @acme/mounting-hardware@1.0.0. If the name comes from the model using the package, read it with load(name, { from: 'project' }).
```

A name that comes from the project using the package, such as a STEP file a part takes as a parameter, is that project's file. Read it with `load(name, { from: 'project' })`. In your project's own files, `load()` reads the project's `imports/` either way.

## Units

`load()` needs no unit. STEP files carry theirs, the import is cached in millimetres, and `load()` scales it into the loading file's [unit](/docs/extra/units): a factor of 1 in a millimetre file, so existing projects are untouched. `load("bracket", { unit: 'in' })` is an assertion for assets with no trustworthy metadata (a `.brep` copied into `imports/` by hand, a STEP whose header is wrong); it overrides what the import recorded, and you should leave it out otherwise.
