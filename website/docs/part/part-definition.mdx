# part()

`part(name, callback)` declares a named part. Everything the callback does — sketches, features, connectors, exposures, parameters, properties — belongs to that part.

```js
import { part, sketch, circle, extrude } from 'fluidcad/core';

export const disc = part('Disc', () => {
    sketch('xy', () => {
        circle([0, 0], 40);
    });
    extrude(5);
});
```

## In the viewport

Click **Part** on the toolbar. FluidCAD appends `part('Part N', () => {})` to the file, activates it, and routes the next features into its body. Rename it from the timeline row's right-click menu. There is no Apply: the statement is written the moment you click.

## The definition is lazy

`part()` returns a **definition**, not built geometry. The callback runs:

- when the file renders on its own — the open part file stays what-you-see-is-what-you-get, so a part nothing exports or inserts still shows in the viewport;
- once per **variant** when an assembly inserts it: `insert(def)` and `insert(def, { Width: 120 })` are two builds, while two `insert(def, { Width: 120 })` share one.

Because the body runs later, it must be self-contained: read parameters with [`param()`](./param) inside the callback, not from variables computed outside it.

## Arguments

| Argument | Meaning |
|----------|---------|
| `name` | The part's display name — in the timeline, the Parts panel, and the STEP product tree on export. |
| `callback` | The body. Its return value is ignored; publish geometry with [`expose()`](./expose). |

## What the definition gives you

| Member | Meaning |
|--------|---------|
| `def.features.<name>` | The source object an [`expose()`](./expose) published, for another part to build on: `extrude(15, donor.features.profile)`. |
| `def.properties.<name>` | A value a [`property()`](./property) published, from the default variant: `donor.properties.pocketDiameter`. |
| `insert(def)` | In an assembly: an instance of the part with `instance.connectors.<name>`, `instance.features.<name>` and `instance.properties.<name>` bound to it. |

## Material

A part can carry a material, and Shape properties turns its volume into a mass with that material's density.

1. Right-click the part's row in the History panel and choose **Set material…**.
2. The **Set material** dialog lists the built-in materials under **Built-in** and the custom ones under **Custom** — the project's own, tagged *in project*, and yours from Settings → Materials. The current one is checked; **None** removes the material. Click a row and **Apply**.
3. Open **Shape properties** (the scale icon at the bottom right), choose the **Part** tab, click the part in the viewport — every solid of the part highlights — and click **Calculate**.

The pick is a `.material('<id>')` chain on the `part()` statement, next to where `.name()` goes. The argument is an id, never a density:

| Id | Where it comes from |
|----|---------------------|
| `fluidcad-steel-1020`, `fluidcad-stainless-304`, `fluidcad-aluminum-6061`, `fluidcad-aluminum-1060`, `fluidcad-aluminum-7075`, `fluidcad-brass-c260`, `fluidcad-copper`, `fluidcad-titanium-6al4v`, `fluidcad-cast-iron-gray`, `fluidcad-bronze`, `fluidcad-pc`, `fluidcad-abs`, `fluidcad-pla`, `fluidcad-nylon-pa6`, `fluidcad-carbon-fiber`, `fluidcad-pine`, `fluidcad-carbon-steel` | Built in. Always available; listed under **Built-in**. |
| `alloy-steel`, `acme-pla`, … | A key of the `materials` map in the project's [`fluidcad.json`](/docs/project-configuration#materials). Listed under **Custom**, with your own materials from [Settings → Materials](/docs/user-interface#your-own-materials); applying one of those copies its entry into the map, so the project carries what it uses. |

A material that is in neither list is added first — to Settings → Materials, or by hand to `fluidcad.json` — then picked. An id the lists do not know is a warning rather than a build error: the part still builds, its row shows a warning triangle, and Shape properties reads `Unknown material: <id>` with no mass.

Only parts carry a material. A solid outside any part is measured with a material picked in Shape properties for that calculation alone; nothing is written to the file. See [Shape properties](/docs/user-interface#shapes-and-shape-properties).

## Export it

An assembly can only insert what the part file exports:

```js
export const bracket = part('Bracket', () => { /* … */ });
```

The Insert dialog scans the workspace for exported definitions and lists each with a thumbnail and the file it came from. Two files may each export a `part` — the assembly's import gets a local alias automatically when the dialog writes it.

## Fusion boundary

Solids inside a part fuse with each other and with nothing outside it: put a bolt and the bracket it sits in into two parts and they stay two solids. Inside one part, `.new()` keeps a feature as a separate body.

## Units

The part's numbers are in its file's unit. Inserted into a project with a different unit it is rescaled on the way in — a 2 in boss is 50.8 mm in a millimetre assembly. `insert(def, { Length: 10 })` means 10 in the **part's** unit. See [Units](/docs/extra/units).
