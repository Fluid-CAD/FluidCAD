# Import DXF

Bring a 2D drawing into a sketch: a laser profile, a supplier's outline, a logo, a legacy 2D part. The **DXF** tool reads the file, lets you place it by hand, and writes its curves as the sketch's own entities — `line`, `arc`, `circle`, `ellipse` and `bezier` statements you can drag, constrain, trim and extrude like anything you drew yourself.

The file is read once. Nothing links the sketch to it afterwards: editing the DXF later does not change the model, and the file does not need to travel with the project.

## In the viewport

1. [Start or reopen a sketch](/docs/sketching/introduction#starting-a-sketch).
2. Click **DXF** on the sketch toolbar (its tooltip is **Import DXF**; the shortcut is <kbd>dx</kbd>).
3. In the **Import DXF** dialog, click **Choose DXF…** and select the file. The drawing appears on the sketch plane at once, inside a frame with handles.

4. Place the drawing with the handles, and set its unit, scale and layers in the dialog. Both are described below.
5. Click **Import**. FluidCAD writes one statement per curve into the sketch body, and a `coincident` constraint wherever two ends meet.

To try it, save the [sample mounting plate](/img/docs/sketching/mounting-plate.dxf) and import it into a sketch on the XY plane.

### Unit

A DXF usually says which unit it is drawn in. The **File unit** select then reads **Same as file (mm)** (or in, cm, …) and the drawing is converted into the document's unit: a 2 in hole in an inch drawing becomes a 50.8 mm hole in a millimetre document.

When the file does not say, the select reads **Document unit (mm)**: the numbers are taken as they are, in the document's unit. If the drawing comes out 25.4 times too small or too large, pick the unit it was really drawn in.

### Layers

Each layer of the file that has curves on it gets a tick box with its number of curves. Layers that are switched off or frozen in the file are marked **off** and start unticked — they are usually notes, borders and construction lines the drawing's author was not looking at either. Tick them to bring them in.

### Joins

A sketch does not treat two ends as connected because they share coordinates; a [coincident](/docs/sketching/constraints/introduction) constraint connects them. With **Join ends that meet** on, the import writes one wherever ends are within a thousandth of a millimetre of each other, so an imported outline stays in one piece when you drag part of it. It starts on when the sketch's **Infer while drawing** setting is on.

Turn it off to get the geometry alone. The outline still forms closed profiles and extrudes; it just comes apart when dragged.

### Fix in place

By default an import is free geometry: it sits where the file drew it, and you can drag any part of it. Turn **Fix in place** on to pin it there instead, so the sketch is fully constrained the moment it is imported — useful for a profile that should be used as it is, or as a fixed outline to build other geometry against.

The import then also writes:

- a `fix` on every point — once per meeting point when ends are joined, so nothing is stated twice;
- a `radius` on every arc and a `diameter` on every circle;
- both semi-radii of every ellipse, and `horizontal` or `vertical` when it lies along a sketch axis;
- a `fix` on every control point of a bezier.

To change part of a fixed import, delete the constraints that hold it (pick the glyph or the dimension and press <kbd>Delete</kbd>) and add your own. Two details:

- An arc of about a half turn is not held by a radius: with both ends fixed, its radius barely changes as it bulges, so the constraint would hold nothing. Its centre is held level with its start instead (`vertical(a.start(), a.center())`), or at a distance from it along one axis.
- An ellipse turned off the sketch axes keeps one degree of freedom, its angle: no constraint holds it.

## Move, scale and rotate

| Action | Gesture |
|---|---|
| Move | Drag the drawing. |
| Scale | Drag a corner handle. The opposite corner stays in place; the drawing always keeps its proportions. |
| Rotate | Drag the knob above the drawing's top edge. |
| Rotate in steps | Hold <kbd>Shift</kbd> while rotating to snap to 15° increments. |

A drawing made near its file's origin lands **as drawn**: its coordinates become sketch coordinates, so a [view exported from FluidCAD](/docs/import-export/export#dxf-and-svg) comes back exactly where the model is. A drawing made far from its origin — a detail somewhere on a large sheet — starts in the middle of the view instead. **As drawn** and **Centre in view** switch between the two at any time. If the drawing is larger than what the view shows, the camera zooms out to it.

<kbd>Esc</kbd> cancels a drag in progress first; otherwise it leaves the tool without importing.

## What is imported

| In the file | In the sketch |
|---|---|
| Line | `line` |
| Circle | `circle` |
| Arc | `arc` |
| Polyline, with or without arc segments (bulges) | One `line` or `arc` per segment |
| Ellipse | `ellipse` |
| Elliptical arc | A few cubic `bezier` curves that follow it closely |
| Spline | Its own Bézier pieces, as `bezier` statements: the same curve |
| Block reference (insert) | The block's contents, in place: moved, turned, scaled, mirrored, arrayed |

Text, dimensions, leaders, hatches, points and images are not curves and are left out: they annotate a drawing, and a sketch holds the geometry a feature is made from. The dialog's **Warnings** section lists how many of each it skipped. A curve drawn twice in the file is written once. Only model space is read.

A sketch has no statement for an elliptical arc, a weighted (rational) spline or a spline above degree three. These are written as cubic beziers that stay within a ten-thousandth of a millimetre of the original, and **Warnings** says how many there were.

## After importing

Unless you imported with [Fix in place](#fix-in-place), the entities sit at the positions the file gave them but are not yet dimensioned: the status at the bottom of the viewport reports the degrees of freedom that remain. They extrude as they are. To make the sketch driven by dimensions, [constrain](/docs/sketching/constraints/introduction) it the usual way — pin a point, add horizontal and vertical constraints, dimension the sizes that matter.

In the code, the import is plain sketch statements, with coordinates written to more decimals than a clicked point so corners, tangencies and centres stay as exact as the file had them:

```js
sketch("xy", () => {
  const l1 = line([-52, -35], [52, -35]);
  const a1 = arc([52, -35], [60, -27], [52, -27]);
  const l2 = line([60, -27], [60, 27]);
  // …
  const c1 = circle([-48, -23], 6);
  coincident(l1.end(), a1.start());
  coincident(a1.end(), l2.start());
  // …
});
```

One import writes up to 2,000 sketch entities. A larger drawing is refused with its count; untick layers to bring it in by parts, or simplify it in the program that made it. Binary DXF and DWG files are not read: save the drawing as an ASCII DXF first.

To trace over a picture instead of importing curves, use a [Reference Image](/docs/sketching/tools/reference-image). A vector drawing saved as SVG is imported the same way with [Import SVG](/docs/sketching/tools/import-svg).
